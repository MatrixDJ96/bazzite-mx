A Bazzite host that has never run the image

  1. Rebase once through the unsigned transport. On an NVIDIA machine name bazzite-mx-nvidia-open or bazzite-mx-nvidia instead.

    sudo rpm-ostree rebase ostree-unverified-registry:ghcr.io/matrixdj96/bazzite-mx:stable

    The rebase keeps whatever the host had layered; the migration's step 3 removes it. When it fails on a local package the image also ships, drop that request in the same transaction:

    rpm-ostree status --json | jq '.deployments[0]["requested-local-packages"]'
sudo rpm-ostree upgrade --uninstall=<name>-<version>-<release>.<arch>

  2. Reboot into the new deployment.

    systemctl reboot

  3. Run the migration from a terminal: without one nothing is confirmed and the run stops. plan is read-only.

    ujust migrate           # plan
ujust migrate apply     # every step asks first

    Both print the plan, then stop on a pending deployment. They also stop on a booted image whose policy has no ghcr.io/matrixdj96 scope, which means step 1 has not run. A local policy.json shadowing the image's is named in that abort, and apply offers to restore it. Then, each step behind its own confirmation and skipped when already done:

    StepWhat it does
    0restores policy.json and registries.d from the image, backup kept
    2backs up the status and fstab, pins the booted deployment, stops uupd.timer for the run
    3rpm-ostree uninstall --all, dry run shown first: layered, local and inactive requests alike
    4rpm-ostree initramfs --disable, so the image's initramfs boots
    5rpm-ostree rebase onto ostree-image-signed:docker://ghcr.io/matrixdj96/<image>:stable
    6rewrites the ntfs rows of fstab to ntfs3, type column only, after proving the driver loadable
    6bmoves leftover ntfsplus files and a host's own modules-load file for msi-ec into the backup, and deletes ntfsplus kernel arguments
    7prints what stays with each user, then rpm-ostree status

    Declining step 3, 4 or 5 aborts the run; declining 6 or 6b only skips it. Step 6 is skipped on a host that opted into NTFSPLUS. The three rpm-ostree steps land in one pending deployment.

  4. Reboot, then check the host. Every line is OK:, or names its fix.

    systemctl reboot
ujust verify-host

What stays with you

Nothing is uninstalled from Flatpak. The Firefox RPM reads ~/.mozilla and the Flatpak keeps its profile in ~/.var/app, so copy it before the first RPM start. Teams is a Flatpak you install yourself.

[ -d ~/.mozilla ] || cp -a ~/.var/app/org.mozilla.firefox/.mozilla ~/
flatpak uninstall org.mozilla.firefox          # when you are done with it
flatpak install flathub com.github.IsmaelMartinez.teams_for_linux

Rollback at any point before the unpin: rpm-ostree rollback && systemctl reboot. After a day of use, unpin the old deployment with sudo ostree admin pin -u <index>. rpm-ostree status prints that index.

A host already on the image

ujust verify-host is the whole procedure: one OK:, FAIL:, SKIP: or INFO: line per check, exit 1 on any FAIL:. The lines a host is most likely to see:

FAIL lineFix
bootc status reports the booted deployment incompatibleujust migrate: an rpm-ostree group is left in the origin
origin is not ostree-image-signed:...ujust migrate apply
origin tag is X, not stableujust migrate apply stable: a dated tag never updates
rpm-ostree mutations in the origin: ...ujust migrate, which runs rpm-ostree uninstall --all
policy.json has no sigstoreSigned scopeostree admin config-diff, then ujust migrate apply
MSI host: msi_ec not loadedujust setup-msi enable
NVIDIA GPU present but the image is bazzite-mxrebase to bazzite-mx-nvidia-open, or bazzite-mx-nvidia for the closed driver
fstab: <target> uses type ntfs without the ntfsplus opt-inujust setup-ntfsplus enable, or ujust migrate for ntfs3
fstab: <target> is <type> but not mounteda dirty NTFS volume is the usual reason: a full shutdown on Windows, or ntfsfix -d

The complete map, one row per line, is in docs/migration.md. An INFO: line is not a failure: the Firefox Flatpak still installed, the ntfs driver not registered yet, fstab rows left on ntfs-3g.
