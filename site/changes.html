What changes

A change enters the image on four conditions. Bazzite must not cover it already. It must need the image layer, be used by a machine that runs the image, and ship a smoke test with its source cited.

Signing trust for these images

Bazzite verifies ghcr.io/ublue-os/* and says nothing about downstream images. This image installs its own key and a policy scope for ghcr.io/matrixdj96, so a host checks every pull of it (verify).

Setup hooks at boot and at login

The base ships no hook dispatcher. ublue-setup-services from the Universal Blue COPR runs system hooks at boot and user hooks at login. That is how wheel members get the docker and libvirt groups, and how each account gets its editor extensions. A hook converges instead of stamping a version, so an account created later is picked up at the next boot.

Docker CE next to Podman

Bazzite ships Podman only. The image adds Docker CE with the buildx and compose plugins from Docker's own repository, and leaves both sockets enabled. It loads iptable_nat for docker-in-docker and brings Fedora's podman-compose, podman-machine, podman-tui and bcvk. The docker group is root-equivalent: wheel members get it at boot, and gpasswd -d <user> docker takes it away.

Virtualization in the image

Bazzite installs the virt-manager Flatpak and enables the monolithic libvirt daemon per host. Here libvirt with the modular daemons, QEMU/KVM, virt-manager, virt-viewer, swtpm and quickemu are in the image. The Flatpak is denied through the base's filter, and the libvirt group is granted to wheel at boot. That leaves ujust setup-virtualization the status report and the opt-in kvmfr module for Looking Glass.

Editor and runtimes

Visual Studio Code is Microsoft's RPM, so it follows the image and its updater is off in the seeded settings. A login hook installs the containers, remote containers and remote SSH extensions for any account that lacks them.

mise comes from the COPR its documentation names and is activated for interactive bash. Its seeded config names node lts, python 3.14, java temurin-21 and dotnet 10, which ujust setup-dev install provisions per user.

Command-line and git tools

gh, glab, ShellCheck and shfmt are in the image. So is a system-administration set: android-tools, bcc and its tools, bpftop, bpftrace, ccache, flatpak-builder, iotop-c, nicstat, numactl, ripgrep, sysprof and trace-cmd. All from Fedora, none in the base.

GitKraken is an RPM from the vendor's own URL rather than a Flatpak, next to git-credential-libsecret. That RPM carries no OpenPGP signature, so the build checks its payload digests before installing it.

Desktop applications

Firefox returns as an RPM, because 1Password's browser integration goes through a host binary a sandboxed Firefox cannot reach. Its Flatpak is denied through the base's filter, and one already installed stays until you remove it. gparted comes from Fedora.

1Password is installed at build time, which is what keeps bootc status compatible where layering it on the host would not. Teams is not preinstalled: the migration recipe prints the Flatpak install command instead.

Sunshine as an RPM

Bazzite dropped its Sunshine RPM for the Flatpak, which cannot do KMS capture. The RPM from the LizardByte COPR is in the image with the capabilities, udev rules and user unit its package ships. That unit is disabled for every user, so streaming is opt-in through ujust setup-sunshine enable.

KDE defaults

Two Plasma update scripts reach existing accounts at their next login as well as new ones. The clock shows seconds, and every screen without a panel gets a bottom panel like the primary one. Seeded Konsole and PowerShell files give new accounts Windows-style Ctrl+C and Ctrl+V, while Ctrl+C still interrupts the shell when nothing is selected.

MSI laptop: kernel modules and MControlCenter

Fan curves, shift modes, keyboard backlight and battery thresholds of an MSI laptop are reachable only through its embedded controller. The image builds the out-of-tree msi-ec and acpi_ec modules against its own kernel, unsigned. Nothing loads them until ujust setup-msi enable, which is gated on the DMI vendor and also installs MControlCenter under /usr/local.

NTFSPLUS as a per-host opt-in

The in-kernel ntfs3 is the default for NTFS volumes, and ujust migrate moves fstab rows onto it. NTFSPLUS is the from-scratch NTFS driver of Linux 7.1 that the ogc kernel leaves disabled. It ships blacklisted until ujust setup-ntfsplus enable proves it on a loop image and switches the rows. The generic mount.ntfs helpers are removed, so the type ntfs reaches the kernel rather than FUSE, and ntfs-3g stays an explicit type.

Recipes and the build

Nine ujust recipes come from this image, three of them in place of a Bazzite recipe of the same name (recipes). Every feature is one build script with one smoke test that runs offline, and the build ends with bootc container lint --fatal-warnings. Every guard has to fail on known-bad input before its first all-clear counts. Each change above is written up with its sources in docs/divergences.md.
