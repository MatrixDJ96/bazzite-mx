What changes

A change enters the image on four conditions. Bazzite must not cover it already. It must need the image layer, be used by a machine that runs the image, and ship a smoke test with its source cited.

Signing trust for these images

Bazzite verifies ghcr.io/ublue-os/* and says nothing about downstream images. This image installs its own key and a policy scope for ghcr.io/matrixdj96, so a host checks every pull of it (verify).

The host names this image

The build rewrites Bazzite's identity: image-info.json, which the shell greeting prints and Bazzite's helpers read, VARIANT_ID and IMAGE_ID in os-release, and the variant on Plasma's About page. The boot menu still reads Bazzite, and Bazzite's rollback helper brh cannot reach this image's tags: a dated release is reached with ujust migrate apply <tag> (FAQ).

Setup hooks at boot and at login

The base ships no hook dispatcher. ublue-setup-services from the Universal Blue COPR runs system hooks at boot and user hooks at login. That is how wheel members get the docker and libvirt groups, and how each account gets its editor extensions and the Konsole and PowerShell files. A hook converges instead of stamping a version, so an account created later is picked up at the next boot or login.

Docker CE next to Podman

Bazzite ships Podman only. The image adds Docker CE with the buildx and compose plugins from Docker's own repository, and leaves both sockets enabled. It loads iptable_nat for docker-in-docker and brings Fedora's podman-compose, podman-machine, podman-tui and bcvk. The docker group is root-equivalent, and every wheel member gets it at every boot; leaving wheel does not take it away (sudo gpasswd -d <user> docker). Its gid is fixed at 995 and libvirt's at 954, and the hook moves a host's own numbers to those.

Virtualization in the image

Bazzite installs the virt-manager Flatpak and enables the monolithic libvirt daemon per host. Here libvirt with the modular daemons, QEMU/KVM, virt-manager, virt-viewer, swtpm and quickemu are in the image. The Flatpak is denied through the base's filter, and the libvirt group is granted to wheel at boot and, like docker, kept on leaving it (sudo gpasswd -d <user> libvirt). That leaves ujust setup-virtualization the status report and the opt-in kvmfr module for Looking Glass. Docker's firewall drops forwarded packets when dockerd enables IP forwarding itself, which cuts a VM on the default network off from the outside: a docker.service drop-in lets the libvirt bridges through Docker's DOCKER-USER chain each time the daemon starts.

Editor and runtimes

Visual Studio Code is Microsoft's RPM, so it follows the image and its updater is off in the seeded settings. A login hook installs the containers, remote containers and remote SSH extensions for any account that lacks them.

mise comes from the COPR its documentation names and is activated for login and interactive bash. Its seeded config names node lts, python 3.14, java temurin-21 and dotnet 10, which ujust setup-dev install provisions per user.

Command-line and git tools

gh, glab, ShellCheck and shfmt are in the image. So is a system-administration set: android-tools, bcc and its tools, bpftop, bpftrace, ccache, flatpak-builder, iotop-c, nicstat, numactl, ripgrep, sysprof, telnet and trace-cmd. All from Fedora, none in the base.

GitKraken is an RPM from the vendor's own URL rather than a Flatpak, next to git-credential-libsecret. That RPM carries no OpenPGP signature, so the build checks its payload digests before installing it.

Desktop applications

Firefox returns as an RPM, because 1Password's browser integration goes through a host binary a sandboxed Firefox cannot reach. It reads Bazzite's Firefox defaults, so its AI features stay off as in the Flatpak. Its Flatpak is denied through the base's filter, and one already installed stays until you remove it. gparted comes from Fedora.

1Password is installed at build time, which is what keeps bootc status compatible where layering it on the host would not. Teams is not preinstalled.

Sunshine as an RPM

Bazzite dropped its Sunshine RPM for the Flatpak, which cannot do KMS capture. The RPM from the LizardByte COPR is in the image with the capabilities, udev rules and user unit its package ships. That unit is disabled for every user, so streaming is opt-in: start it with ujust setup-sunshine enable, which sets the portal's credentials first.

KDE defaults

Two Plasma update scripts reach existing accounts at their next login as well as new ones. The clock shows seconds, and every other screen without a panel gets a bottom panel like the primary one. Each runs once per account: a later change to one reaches new accounts only, and ujust setup-panels applies the current panel script. A Konsole file and a PowerShell profile come from /etc/skel for a new account and from a login hook for one that predates the image: Ctrl+C copies in Konsole while it still interrupts the shell when nothing is selected, and Ctrl+C with Ctrl+V copy and paste in a pwsh the user installs, PowerShell not being in the image.

MSI laptop: kernel modules and MControlCenter

Fan curves, shift modes, keyboard backlight and battery thresholds of an MSI laptop are reachable only through its embedded controller. The image builds the out-of-tree msi-ec and acpi_ec modules against its own kernel, unsigned. Stock Bazzite loads its own signed msi-ec at boot on any MSI laptop, Secure Boot on or off; here nothing loads them until ujust setup-msi enable, which is gated on the DMI vendor, needs Secure Boot off and also installs MControlCenter under /usr/local.

NTFSPLUS as a per-host opt-in

The in-kernel ntfs3 is the default for NTFS volumes, and ujust migrate moves fstab rows onto it. NTFSPLUS is the from-scratch NTFS driver of Linux 7.1, built from its author's tree at a pinned commit. It ships blacklisted until ujust setup-ntfsplus enable proves it on a loop image and switches the rows, each ntfs row gaining errors=remount-ro: NTFSPLUS's own default, errors=continue, would mount a dirty or hibernated volume writable. No mask is written, so a row without one goes from 0755 under ntfs3 to 0777, writable by every account. The module is unsigned, so Secure Boot has to be off. The generic mount.ntfs helpers are removed, so the type ntfs reaches the kernel rather than FUSE, and ntfs-3g stays an explicit type. Bazzite's warning about running games from NTFS drives (ntfs-nag) is off for every user, an NTFSPLUS volume being of type ntfs.

Recipes and the build

Nine ujust recipes come from this image, three of them in place of a Bazzite recipe of the same name (recipes). Every feature is one build script with one smoke test that runs offline, and the build ends with bootc container lint --fatal-warnings. Every guard has to fail on known-bad input before its first all-clear counts. Each change above is written up with its sources in docs/divergences.md.

A single-maintainer image, built in the open, not affiliated with Bazzite or Universal Blue. Rebase at your own risk. Source under Apache-2.0.
