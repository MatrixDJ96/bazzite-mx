From any machine

The key is cosign.pub in the repository, the same file the image installs as /etc/pki/containers/matrixdj96.pub. The signature sits on the digest, so it holds whichever tag you name. Each release run also records a build provenance attestation in GitHub's store, tied to this repository and to the digest it built.

cosign verify --key https://raw.githubusercontent.com/MatrixDJ96/bazzite-mx/main/cosign.pub \
  ghcr.io/matrixdj96/bazzite-mx:stable

gh attestation verify oci://ghcr.io/matrixdj96/bazzite-mx:stable --repo MatrixDJ96/bazzite-mx

Name another image or a dated tag to check that one. gh needs a registry login, since an oci:// reference is fetched from an authenticated registry.

The SBOM

The packages of each image are listed in an SPDX document, attached to the image as a referrer and signed with the same key. The release notes print the diff between two releases; the document itself is one oras call away.

oras discover --format json ghcr.io/matrixdj96/bazzite-mx:stable \
  | jq -r '.referrers[] | select(.artifactType == "application/vnd.spdx+json") | .digest'

What the host verifies

After ujust migrate the origin is ostree-image-signed:docker://ghcr.io/matrixdj96/<image>:stable. The image's /etc/containers/policy.json carries the ghcr.io/matrixdj96 scope as sigstoreSigned with the key above, and keeps default on reject. The tag stays free while the signature is checked on the digest, and a failing pull is refused before anything is staged.

ujust verify-host prints the policy in force (install). A local copy of policy.json shadows the image's, which is why the migration recipe offers to restore it first.

How a release is gated

A push never publishes. A release is a dispatched run: by hand, by the weekly trigger, or by the watcher. That watcher compares the base's digest with the one the current :stable was built from. The run builds the three images, probes each one, pushes it to :staging, signs it and records the attestation. A separate job verifies all of that again by digest, with two negative controls. Only then does the run write the dated tag; it moves :stable only when the dispatch asks for it (docs/workflow.md).
