Is this Bazzite?
It is built on Bazzite's images and follows their stable stream. It stays a personal image with one maintainer, public and usable at your own risk. Bazzite's documentation covers everything it does not change, and what changes lists what it does.
Which image is mine?
bazzite-mx for AMD or Intel graphics, bazzite-mx-nvidia-open for an NVIDIA GPU the open kernel modules cover, bazzite-mx-nvidia for the rest. lspci -d 10de: says whether there is an NVIDIA GPU.
Why does the first rebase go through the unsigned transport?
A signed pull is checked against the policy of the deployment that runs it, and stock Bazzite carries no trust for ghcr.io/matrixdj96. After that one pull, the policy inside the image checks every later pull (verify).
What happens to the packages I layered on Bazzite?
ujust migrate removes them all, with a dry run shown first, because bootc marks a deployment incompatible on any rpm-ostree group. What you need on top goes to Flatpak, Homebrew or a distrobox; what needs the image layer is a change to the image.
Why are the Firefox and virt-manager Flatpaks denied?
Both are RPMs in the image, so a Flatpak would be a second copy one click away in Discover. The Firefox profile is copied by hand (install).
I have an MSI laptop and the modules do not load.
msi-ec and acpi_ec are unsigned, so lockdown refuses them while Secure Boot is on. Check bootctl status; with Secure Boot off, ujust setup-msi enable loads them and installs MControlCenter.
ntfs3, ntfs or ntfs-3g: which driver mounts my NTFS volumes?
ntfs3 by default, and ujust migrate rewrites fstab rows onto it. The type ntfs is the NTFSPLUS driver, used only after ujust setup-ntfsplus enable. ntfs-3g is the FUSE driver and stays available as an explicit type. On a host that did not opt in, mount -t ntfs fails with an unknown filesystem type instead of landing on FUSE.
How do I go back?
rpm-ostree rollback && systemctl reboot boots the previous deployment again; the migration recipe pinned it, so it survives garbage collection until you unpin it. To leave the image, rebase to any Bazzite image the way you arrived.
Can I build it myself?
Yes: podman build with BASE_IMAGE and IMAGE_NAME as build arguments. The build runs the smoke tests and ends with bootc container lint --fatal-warnings (the repository).
Something is wrong. Where do I say so?
In the repository's issues, with the output of ujust verify-host and, for a pull, of rpm-ostree status.
