Get the image

ghcr.io/matrixdj96/ bazzite-mx:stable

A personal bootc image on Bazzite, KDE desktop, stable stream. Kernel modules, services, vendor repositories, signing trust and the ujust recipes are in the image; applications stay on Flatpak, mutable userspace in a distrobox.

Pick your image

Only the base image differs. lspci -d 10de: prints a line when there is an NVIDIA GPU; no line means the first image.

AMD or Intel graphics

ghcr.io/matrixdj96/bazzite-mx:stable

on ghcr.io/ublue-os/bazzite:stable

NVIDIA, open kernel modules (Turing and newer)

ghcr.io/matrixdj96/bazzite-mx-nvidia-open:stable

on ghcr.io/ublue-os/bazzite-nvidia-open:stable

NVIDIA, closed driver (Maxwell, Pascal and Volta)

ghcr.io/matrixdj96/bazzite-mx-nvidia:stable

on ghcr.io/ublue-os/bazzite-nvidia:stable

Follow :stable: it moves only onto a release the gate has verified. The images page has the dated tags, the update command and the rollback.

Five commands

From a Bazzite host. The first rebase is unsigned, because stock Bazzite trusts nothing under ghcr.io/matrixdj96; ujust migrate then moves the host onto the signed origin, asking before every change except those of step 2: the backups, the pin and the timer stop.

sudo rpm-ostree rebase ostree-unverified-registry:ghcr.io/matrixdj96/bazzite-mx:stable
systemctl reboot
ujust migrate apply
systemctl reboot
ujust verify-host

On an NVIDIA machine name bazzite-mx-nvidia-open (Turing and newer) or bazzite-mx-nvidia (Maxwell, Pascal and Volta) in the first line; an older GPU stays on bazzite-mx. Every step, with what it removes and what stays: install.

What the image adds

Every change enters on four conditions: Bazzite does not cover it, it needs the image layer, a machine that runs the image uses it, and it ships a smoke test with its source cited.

Signing trust

A key and a policy scope for ghcr.io/matrixdj96: a host checks every pull.

Docker CE next to Podman

Engine, buildx and compose from Docker's repository, both sockets on.

Virtualization

libvirt, QEMU/KVM, virt-manager, swtpm and quickemu in the image, VMs reach the network past Docker's firewall.

Editor and runtimes

Visual Studio Code as Microsoft's RPM, mise for per-user node, python, java and dotnet.

Command-line and git tools

gh, glab, ShellCheck, shfmt, GitKraken and a tracing set.

Desktop applications

Firefox and 1Password as RPMs, so the browser integration works; gparted.

Sunshine as an RPM

KMS capture the Flatpak cannot do, streaming opt-in per user.

KDE defaults

Clock seconds, a panel per screen, Ctrl+C to copy in Konsole, Ctrl+C and Ctrl+V in a pwsh you install.

MSI laptop

msi-ec and acpi_ec built against the kernel, MControlCenter on request.

The rest is on what changes: the setup hooks that run at boot and at login, the NTFSPLUS driver as a per-host opt-in, and the recipes that migrate, verify and set up a host.

Verified before it is pulled

Every published image is signed by digest with cosign.pub, the key the image itself trusts, and attested by the workflow run that built it. A push never publishes: a release is a dispatched run whose gate verifies the signature by digest before the dated tag or :stable points at the image.

cosign verify --key https://raw.githubusercontent.com/MatrixDJ96/bazzite-mx/main/cosign.pub \
  ghcr.io/matrixdj96/bazzite-mx:stable

The attestation, the SBOM and what a migrated host checks on its own: verify.
