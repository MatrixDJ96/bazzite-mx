Get the image

Images

Three flavours from one recipe. The base image is the only difference, and each flavour gets its kernel modules built against the kernel of its own base.

Which image

AMD or Intel graphics

ghcr.io/matrixdj96/bazzite-mx

on ghcr.io/ublue-os/bazzite:stable

NVIDIA, open kernel modules (Turing and newer)

ghcr.io/matrixdj96/bazzite-mx-nvidia-open

on ghcr.io/ublue-os/bazzite-nvidia-open:stable

NVIDIA, closed driver (Maxwell, Pascal and Volta)

ghcr.io/matrixdj96/bazzite-mx-nvidia

on ghcr.io/ublue-os/bazzite-nvidia:stable

An NVIDIA GPU answers on the bus as vendor 10de. No line means the first image, and so does a GPU older than Maxwell, which no NVIDIA flavour drives.

lspci -d 10de:

The closed-driver base carries its own kernel. ujust verify-host catches a host on the wrong flavour: an NVIDIA GPU on bazzite-mx, or no NVIDIA GPU on an NVIDIA image.

Tags

TagWhat it points at
:stable the tag a host follows; it moves only onto a release the gate has verified
:<fedora>.<yyyymmdd>[.<n>] one release, never moved; the first number is the Fedora version of the base, the last one, when present, numbers a further release of that day (.1 for the second)
:staging what the last release run pushed before its gate, re-pointed by every run

The exact name of every dated tag is on the releases page with the digest of each image and the package changes since the previous release. GHCR keeps every dated tag younger than 90 days and the 7 newest older ones, while every release page stays. A host pinned to a dated tag never updates, so to try a release and come back:

ujust migrate apply <tag>    # a dated tag, named as on the releases page
ujust migrate apply          # back to stable

Updates and rollback

After the migration the host updates the Bazzite way: uupd on its timer, or by hand. The previous deployment stays on disk and boots from the boot menu, whose entries read Bazzite (ostree:N), the newest first, without a version: one per deployment, and a migration pin keeps one more than usual. rpm-ostree status names them before the reboot.

sudo bootc upgrade          # fetch and stage the next :stable, reboot to use it
rpm-ostree rollback         # make the previous deployment the default again
systemctl reboot

A pull from ghcr.io/matrixdj96 is checked against the key the image carries, so a release without a valid signature is refused before staging; a registry the policy does not name is pulled unverified (verify).
